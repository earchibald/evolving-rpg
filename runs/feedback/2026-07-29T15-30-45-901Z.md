# Filed, not played

> A world was born and spent in one turn so a single sentence about a refused item could reach the record — the fun is not broken here, the reporting is.

*world main · ended playing at turn 1, depth 1 · submitted: wipe · 0 take(s), spoke: false*

## findings

- **This is a bug report wearing a run's clothes.** Turn 1, 0 steps, 0 swings, 0 takes, 10/10 hit points, five creatures untouched, no rule fired. The only human thing in the whole packet is a typed, out-of-world note: *"bug with item pickup/swap/no-better-than encountered"*. Nothing in the chain corresponds to it — you cannot pick up nothing in zero steps. The mechanism that failed is the **filing path**: the only way to say "something is wrong" is to attach a note to a run, so the player spent a world to spend a sentence. The moment they actually saw is in some earlier session that never got submitted.

- **The refusal they hit leaves no trace in the chain by design.** The "no better than" line is a *view* string in `src/ui/debug.ts:1735-1775`, printed after the fact from a re-fold; a refused pickup emits **no event at all** (the comment there says so out loud: "produces no event at all — the one case where the engine's silence reads as a bug"). So the chain sentence *"You picked up 0 things"* is identical whether the floor was bare or the game said no to your face. Every lens, every future Listener, and the player's own history are blind to refusals. That is why this report has "(no readings)" where the interesting thing was.

- **The no-better branch is the one refusal that doesn't hand you the key.** Read the four refusal lines in that block together: satchel full → *"type , to swap your first thing out"*; scroll in hand → *"type , to swap"*; a tradeoff → *"asks a trade — type , to take it"*; and then dominated gear → *"is no better than your X — it stays where it lies"*, full stop. But `takeUnderfoot` (`src/core/commands.ts:1409-1411`) explicitly accepts "tradeoffs and downgrades alike" on a chosen take. So the game **will** give you the item and **tells you it won't**. That is exactly the seam the player named — pickup / swap / no-better-than, in that order.

- **Press `,` and get nothing, hear nothing.** The whole explanation block is gated on `fresh.some(e => e.type === 'MOVE')`. A chosen take that returns `null` — heart-sealed satchel, empty tile, a mis-timed key — produces no event, therefore no MOVE, therefore no line. The key that three of the four messages point at is the one key that can answer with total silence. Illegible cause: the player cannot tell "I pressed the wrong thing" from "the game is broken," so they file it as broken.

- **Zero is not a reading.** No steps, no blows, no deaths, no rule firings, no lens data. There is no decision to evaluate here and no consequence to feel, but that is not a verdict on the design — it is an empty sample. The honest statement is that this run measured the tooling, not the game.

## recommendations

1. **One string.** In `src/ui/debug.ts:1771`, append the key to the dominated branch: `"the X is no better than your Y — it stays where it lies; type , to take it anyway"`. Every other refusal in that block already names `,`; this one line makes the view stop contradicting `commands.ts`. Smallest possible change, and it may be the entire reported bug.

2. **Answer a silent `,`.** Move the chosen-take path out from behind the `MOVE` gate: when `takeUnderfoot(chosen: true)` returns `null`, print why — *"nothing lies here"*, *"the heart seals your satchel"*. A key that can do nothing without saying so will keep being reported as a bug.

3. **Give a refusal a shadow in the record.** Not a Forge rule — this is below the rule vocabulary, in the event vocabulary. Add `ITEM_REFUSED { entityId, itemId, reason: 'dominated' | 'sealed' | 'full' | 'scroll-hand' }`, emitted where the engine currently returns `null`. It changes nothing in `fold` (no state), but it puts refusals in the chain, which means lenses can count them and a Listener can finally see the thing this player was trying to point at. Costs: `src/core/events.ts`, `src/log/upcast.ts`, and a golden-replay update — the one big swing, and worth it, because right now the game's most confusing moment is its least recorded one.

4. **Let a note travel without a world.** A packet whose note says "encountered" about a run that never happened means the player had no cheaper way to file. Whatever the submit path is, it should accept a bare note against the *previous* head, so the report lands on the turn where the thing happened instead of on a fresh turn 1.

## the shape of it

There is nothing here to call fun or not-fun — one turn, no contact, no choice made. What this run does say is sharp and worth having: the game's most confusing beat, a prize it refuses to let you take, is deliberately the one beat it does not write down, and the sentence it prints in that moment is both the only refusal that hides the escape key and, per the engine, factually wrong. The single absence that matters most next is **an event for a refusal** — until the chain can see the game saying no, every "no better than" complaint will arrive the way this one did: a whole world burned down to carry eight words.
