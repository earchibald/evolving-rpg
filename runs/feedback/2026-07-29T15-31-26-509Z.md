## findings

- **Turn 1, and every counter is zero.** 0 steps, 0 blocks, 0 waits, 0 swings, 0 blows taken, 0 deaths, 0 pickups, 10/10 hp, stats untouched at 3/4/3, 3 creatures still standing. Nothing in this packet is a record of play. The mechanism isn't "not fun" — it's *no run*. There is no decision, consequence, or cause to evaluate because no input ever reached the world.

- **The guard meant to stop this packet is dead code.** `src/ui/debug.ts:2594` refuses to bother the Listener with `if (state.turn === 0 && !witness.hasVoice()) return;` — but `WORLD_INIT` seeds `turn: 1` (`src/core/apply.ts:161`). A live world is never at turn 0, so the condition can never hold. Every wipe of an untouched world submits a null reading. This packet is the proof: turn 1, no voice, submitted anyway.

- **The silence says nothing, and that is itself the finding.** No spoken words, no typed notes, no lens readings. Ordinarily a flat silence is evidence — a complaint withheld, a run abandoned mid-floor. Here it is structural: the mic, the notes and the lenses all fire *on play*, so a zero-action run produces zero instrumentation by construction. The harness cannot presently tell "the player was bored into silence" apart from "the player never started." Reading feeling into this gap would be inventing it.

- **`reason: 'wipe'` is the only player-authored fact, and it is ambiguous.** `submitToListener('wipe')` fires deliberately before the world is destroyed (`debug.ts:2583` — "the snapshot is taken BEFORE the world mutates"), so the one thing we know is that a human chose *erase* over *play*. But at turn 1 that reading forks two ways — a fed-up quit, or a routine clearing of a scratch world before real work — and the packet carries no discriminator between them. Both live runs would look identical.

- **This run feeds the Forge nothing, and quietly poisons the corpus.** "No rule fired during this run" is trivially true: no rules were in force and no trigger ever occurred. A ratified rule's `provenance.events` would be empty here. Filed unmarked into `runs/feedback/index.jsonl` alongside six real readings, a teardown snapshot dilutes the evidence base the Rulesmith and the Critic draw on — a non-observation shelved as an observation.

## recommendations

1. **Fix the gate (one line, `src/ui/debug.ts:2594`).** Gate on *action*, not on the turn counter, since `turn` is never 0 in a live world. Something to the effect of: suppress the submit when steps + waits + swings + blocks + pickups all read zero and `witness.hasVoice()` is false. Test it against a freshly-born-then-wiped world, which is exactly the case that slipped through today.

2. **Carry `reason` into the feedback index.** `runs/feedback/index.jsonl` should record whether a reading came from `begin-again`, `another-world`, or `wipe`, so a teardown snapshot is filterable and a future sweep isn't reading dungeon design out of a housekeeping click.

3. **Do not mint a rule off this run — and note the gap without filling it.** The vocabulary has `turnAtLeast` but no `turnAtMost`, so no rule can be scoped to fire *only in the opening* — the exact stretch of the run this packet is about. That is a genuine hole in the condition slot. But `docs/design/VOCABULARY.md` §2 is explicit that widening comes *after play shows an absence*, and a zero-turn packet is not that absence. Record the gap; earn it later with a run someone actually played.

4. **Leave the opening-frame tables alone for now.** If a real run later shows the first floor is inert, the knobs are `sightAt` (9 at depth 1) and `spawnBudget` (depth 1) in `src/core/tables.ts` — how much you can see, and how much is out there to see. Neither should be moved on today's evidence, which contains no observation of either.

## the shape of it

The single absence that matters most next is not a mechanic but a *filter* — the Listener must be able to tell a run from a teardown before it can tell fun from boredom.
